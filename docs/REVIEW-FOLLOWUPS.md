task, and which test fails without the fix) or **LEFT** (and why).

## indep-3146 (review of task 3146), follow-ups fixed by task 3151

| ID | Finding | Status | Fix | Regression test |
|---|---|---|---|---|
| R3146-01 (LOW) | The guard checked the repository identity, then every merge git call found the repository again through `.git`. A `.git` swapped in between moved the merge into another repository, and that repository's filter driver ran in the orchestrator. | **FIXED** (task 3151 for the `.git` entry; task 3155 for the work-tree directory, indep-3151 F2), residuals noted | The snapshot also records the checkout's git dir (realpath and inode) and work-tree root. Before the merge the pinned git dirs are opened as directories and their inodes checked. Every git call whose cwd is the main checkout or the task worktree then runs with `--git-dir=/proc/self/fd/N`, `--work-tree=<root>` and `GIT_COMMON_DIR` (`git_repositories_pinned` in `equipa/git_ops.py`). A realpath alone would not do: after a swap the same path leads to the other repository. Task 3151 still looked the pin up by the realpath of the cwd and ran a call that matched no pin unpinned, so swapping the whole checkout (or task worktree) directory for a symlink to a clone sent the merge into the clone again, with its driver. Task 3155: pins are keyed by the path the merge passes (not its realpath), the work-tree directory's device and inode are recorded when the pin is made and checked on every call, and inside a pinned block a cwd that names no pinned work tree raises `PinnedRepositoryError` instead of discovering a repository. The merge path turns that error into a tripped guard. Residuals: (1) git's files ref backend reads the git dir's `commondir` file even when `GIT_COMMON_DIR` is set. A wrong `commondir` is refused when the pin is opened; one planted during the merge can only move refs, and the post-merge identity check trips. (2) The pin fixes which repository git uses, not what is in it: the pinned config, attributes and the worktree's admin dir stay writable by a same-UID process between the hazard scan and `git merge`, so a driver planted *in place* there still runs (EQUIPA R3151-04). The "never config or drivers" guarantee covers redirection only. Closing this needs a separate agent UID. (3) A swap between the per-call inode check and git's own `chdir` cannot change the git dir, so config and drivers still come from the pinned repository, but git would then use the swapped work tree; the post-merge identity check trips. (4) On a system without `/proc/self/fd`, the pin falls back to inode-checked realpaths, which do not survive a rename made after the check. | `tests/test_merge_path_pinned_3151.py` (`test_git_swapped_at_the_merge_cannot_redirect_it`, `test_every_merge_path_git_call_runs_on_the_pinned_repository`, `test_commondir_planted_after_the_pin_runs_no_foreign_driver`); `tests/test_merge_path_pinned_3155.py` (`test_main_checkout_swapped_for_a_symlink_at_the_merge_trips_the_guard`, `test_task_worktree_swapped_for_a_symlink_in_the_rebase_trips_the_guard`, `test_a_cwd_that_names_no_pinned_work_tree_is_refused`, `test_a_real_directory_moved_into_the_pinned_path_is_refused`) |
| R3146-02 (LOW) | The repository-identity alert printed agent-chosen paths raw to stdout and the logger. A newline in a planted directory name started a forged `[GATE-AUDIT]` line in the dispatch log. | **FIXED** | The alert is escaped with `escape_audit_text` when it is built, so stdout, the logger and the task's block reason all carry one line. | `tests/test_merge_path_pinned_3151.py` (`test_newline_in_a_planted_common_dir_cannot_forge_an_audit_line`) |
| R3146-03 (UNVERIFIED, rated MEDIUM) | The check-26 list of integer special variables was hand-kept and missed `BASHPID`. bash ignores a plain `BASHPID=` but evaluates `BASHPID+=` as arithmetic, which expands an array subscript again. | **FIXED** (`BASHPID` by task 3151; `SECONDS` and `MAILCHECK` by task 3155, indep-3151 F1; confirmed by the bash differential before each fix) | `BASHPID`, `SECONDS` and `MAILCHECK` added to `_EVALUATES_TEXT_RE` in `equipa/bash_security.py`. Task 3151 read the integer variables from a bare `declare -p`, which prints `SECONDS` without its integer attribute (bash gives it the attribute only when it computes the value), so `SECONDS+='a[$(…)]'` still ran in a fresh bash while check 26 called it safe. An interactive bash also makes `MAILCHECK` integer. The tests now list every variable with `compgen -v` and read `declare -p NAME` one name at a time, in a non-interactive and an interactive (`-i`) bash. They require each assignable integer one to be on the list, run every assignment form (`NAME=`, `NAME+=`, prefix assignment, `declare -i`, `declare NAME+=`, `let`, `(( ))`, `read`, `printf -v`, `for NAME in`) on each name through the sentinel differential in both kinds of bash, and run every form on every `compgen -v` name in a fresh bash per line, where any name whose own assignment ran the marker must be on the list. Scaled run (6 seeds × 10 000 lines × both kinds of bash, bash 5.2.21): 0 markers that bash ran were proven inert or allowed. | `tests/test_bash_tokenizer_3128.py` (`test_check_26_names_every_assignable_integer_variable_of_this_bash`, `test_check_26_names_the_integer_specials_bash_computes`, `test_integer_variable_assignments_bash_runs_are_never_proven_inert`, `test_every_variable_assignment_bash_runs_in_a_fresh_bash_is_refused`, `test_substitutions_bash_runs_are_never_proven_inert`) |
